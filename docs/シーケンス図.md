## 登場人物（アクター）

| 記号 | 名前 | 説明 |
|------|------|------|
| U | ユーザー | ブラウザを操作する人 |

## 1. レシピ一覧取得フロー

```mermaid
sequenceDiagram
    actor U as ユーザー
    participant FE as フロントエンド
    participant API as API Routes
    participant DB as MySQL(Prisma)

    U->>FE: トップページにアクセス
    FE->>API: GET /api/recipes
    note right of API: クエリパラメータ例<br/>?q=鶏&categoryId=4&favorite=true
    API->>DB: recipes.findMany()<br/>（新着順・カテゴリ結合）
    DB-->>API: レシピ一覧データ
    API-->>FE: 200 OK [Recipe[]]
    FE->>FE: カード形式でレンダリング
    FE-->>U: 一覧ページ表示
```

## 2. レシピ登録フロー（画像あり）

```mermaid
sequenceDiagram
    actor U as ユーザー
    participant FE as フロントエンド
    participant API as API Routes
    participant FS as ファイルシステム
    participant DB as MySQL(Prisma)

    U->>FE: 画像ファイルを選択
    FE->>FE: バリデーション<br/>（形式・サイズチェック）
    alt バリデーション NG
        FE-->>U: エラーメッセージ表示
    else バリデーション OK
        FE->>API: POST /api/upload (FormData)
        API->>API: MIMEタイプ・サイズ検証
        API->>FS: public/uploads/{timestamp}.jpg に保存
        FS-->>API: 保存完了
        API-->>FE: 200 OK { imagePath: '/uploads/xxx.jpg' }
        FE->>FE: 画像プレビュー表示
    end

    U->>FE: フォームに必要事項を入力
    U->>FE: 「登録する」ボタン押下
    FE->>FE: バリデーション（必須チェック）
    alt バリデーション NG
        FE-->>U: エラーメッセージ表示
    else バリデーション OK
        FE->>API: POST /api/recipes<br/>{ title, ingredients, instructions, imagePath, ... }
        API->>API: サーバーサイドバリデーション
        API->>DB: recipes.create(data)
        DB-->>API: 作成されたレシピ
        API-->>FE: 201 Created { recipe }
        FE-->>U: 一覧ページへリダイレクト
    end
```

## 3. レシピ編集フロー

```mermaid
sequenceDiagram
    actor U as ユーザー
    participant FE as フロントエンド
    participant API as API Routes
    participant FS as ファイルシステム
    participant DB as MySQL(Prisma)

    U->>FE: 編集ページにアクセス
    FE->>API: GET /api/recipes/[id]
    API->>DB: recipes.findUnique({ id })
    DB-->>API: レシピデータ
    API-->>FE: 200 OK { recipe }
    FE->>FE: フォームに既存データを表示

    opt 新しい画像を選択した場合
        U->>FE: 新しい画像を選択
        FE->>API: POST /api/upload（新画像）
        API->>FS: 新画像を保存
        API-->>FE: { imagePath: '/uploads/new.jpg' }
        FE->>FE: 新画像のプレビュー表示
    end

    U->>FE: 「更新する」ボタン押下
    FE->>FE: バリデーション
    FE->>API: PUT /api/recipes/[id]<br/>{ 変更後データ }
    API->>DB: recipes.findUnique({ id })<br/>（旧 imagePath を取得）
    opt 画像が変更された場合
        API->>FS: 旧画像ファイルを削除
    end
    API->>DB: recipes.update({ id, data })
    DB-->>API: 更新されたレシピ
    API-->>FE: 200 OK { recipe }
    FE-->>U: 詳細ページへリダイレクト
```

## 4. レシピ削除フロー

```mermaid
sequenceDiagram
    actor U as ユーザー
    participant FE as フロントエンド
    participant API as API Routes
    participant FS as ファイルシステム
    participant DB as MySQL(Prisma)

    U->>FE: 削除ボタン押下
    FE-->>U: 確認ダイアログ表示<br/>「本当に削除しますか？」
    alt キャンセル
        U->>FE: 「キャンセル」選択
        note over FE: 何も起きない
    else 確認OK
        U->>FE: 「削除する」選択
        FE->>API: DELETE /api/recipes/[id]
        API->>DB: recipes.findUnique({ id })
        DB-->>API: レシピデータ（imagePath 含む）
        opt 画像ファイルが存在する場合
            API->>FS: 画像ファイルを削除
        end
        API->>DB: recipes.delete({ id })
        DB-->>API: 削除完了
        API-->>FE: 204 No Content
        FE-->>U: 一覧ページへリダイレクト
    end
```

## 5. お気に入りトグルフロー

```mermaid
sequenceDiagram
    actor U as ユーザー
    participant FE as フロントエンド
    participant API as API Routes
    participant DB as MySQL(Prisma)

    U->>FE: ♡ ボタンをクリック
    FE->>FE: 楽観的更新<br/>（ハートを即座に切り替え表示）
    FE->>API: PATCH /api/recipes/[id]/favorite
    API->>DB: recipes.findUnique({ id })<br/>（現在の isFavorite を確認）
    DB-->>API: { isFavorite: false }
    API->>DB: recipes.update({ isFavorite: true })
    DB-->>API: 更新完了
    API-->>FE: 200 OK { isFavorite: true }
    FE->>FE: UI を確定状態に同期
    alt API エラーの場合
        API-->>FE: 500 Error
        FE->>FE: 楽観的更新を元に戻す
        FE-->>U: エラーメッセージ表示
    end
```
