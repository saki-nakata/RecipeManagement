## 1. インフラ概要

本番環境は AWS 上に構築し、Terraform（IaC）でインフラをコード管理する。
学習目的のため AWS 無料枠の範囲内で構築する。

---

## 2. アーキテクチャ図

```
インターネット
     │ HTTP (port 80)
     ▼
┌─────────────────────────────────────┐
│  EC2 (パブリックサブネット)           │
│                                     │
│  nginx                              │
│  （リバースプロキシ 80 → 3000）      │
│       ↓                             │
│  Next.js (port 3000)                │
│  （PM2 でプロセス管理）              │
└─────────────────────────────────────┘
     │ MySQL (port 3306)
     │ プライベートサブネット内のみ
     ▼
┌─────────────────────────────────────┐
│  RDS MySQL                          │
│  （プライベートサブネット）           │
│  EC2 のセキュリティグループからのみ   │
│  接続許可                           │
└─────────────────────────────────────┘
```

## 3. AWS リソース構成

### 3.1 ネットワーク

| リソース | 説明 |
|---------|------|
| VPC | 本番環境専用の仮想ネットワーク |
| インターネットゲートウェイ | VPC をインターネットに接続 |
| パブリックサブネット | EC2 を配置。外部からアクセス可能 |
| プライベートサブネット（2 AZ） | RDS を配置。外部から直接アクセス不可 |
| ルートテーブル | パブリックサブネットのトラフィックを IGW に向ける |

### 3.2 セキュリティグループ

| 名前 | インバウンド | 用途 |
|------|------------|------|
| EC2 用 SG | 22（SSH）、80（HTTP） | EC2 への外部アクセス制御 |
| RDS 用 SG | 3306（EC2 SG からのみ） | DB アクセスを EC2 に限定 |

### 3.3 EC2

| 項目 | 内容 |
|------|------|
| インスタンスタイプ | t2.micro（AWS 無料枠） |
| OS | Amazon Linux 2023 |
| ストレージ | 20GB（gp2） |
| 配置 | パブリックサブネット |
| 障害対応 | CloudWatch アラームによる自動回復 |

### 3.4 RDS

| 項目 | 内容 |
|------|------|
| インスタンスクラス | db.t3.micro（AWS 無料枠） |
| エンジン | MySQL 8.0 |
| ストレージ | 20GB |
| 配置 | プライベートサブネット（2 AZ） |
| 外部アクセス | 不可（publicly_accessible = false） |
| 自動バックアップ | 7 日間保持（無料枠内） |

## 4. EC2 上のソフトウェア構成

| ソフトウェア | 役割 |
|------------|------|
| Node.js 20 | アプリケーションの実行環境 |
| pnpm | パッケージマネージャー |
| Next.js | フロントエンド + バックエンド（API Routes） |
| Prisma | ORM（DB アクセス） |
| PM2 | Node.js プロセスの常駐・自動再起動管理 |
| nginx | リバースプロキシ（port 80 → port 3000）・アップロード画像の静的配信（`/uploads/`） |

## 5. IaC（Terraform）

インフラ構成は Terraform でコード管理する。

```
terraform/
├── provider.tf          # AWS プロバイダー設定（ローカル state）
├── variables.tf         # 変数定義
├── main.tf              # 全 AWS リソース定義
├── outputs.tf           # 出力値（EC2 IP・RDS エンドポイント等）
├── user_data.sh.tpl     # EC2 起動時の自動セットアップスクリプト
└── terraform.tfvars     # 実際の変数値（.gitignore 済み・機密情報含む）
```

> `terraform.tfvars` および `terraform.tfstate` は機密情報（DB パスワード等）を含むため `.gitignore` で除外管理する。

## 6. デプロイフロー

### 6.1 初回構築

```
terraform init
terraform plan   # 変更内容を確認
terraform apply  # AWS リソースを作成
```

EC2 起動後、`user_data.sh.tpl` が自動実行され以下の処理を行う：
1. スワップ領域の確保（メモリ不足対策）
2. Node.js・pnpm・PM2・nginx のインストール
3. GitHub からアプリのクローン
4. 依存パッケージインストール・Prisma クライアント生成・ビルド
5. PM2 でアプリ起動・自動起動設定
6. nginx の起動と reverse proxy 設定

### 6.2 コード変更時のデプロイ（ローカルから）

```bash
# プロジェクトルートで実行
bash scripts/deploy.sh
```

スクリプトの処理内容：
1. rsync でローカルのソースファイルを EC2 に転送（差分のみ）
2. EC2 上で `pnpm install` → `prisma generate` → `next build`
3. PM2 を再起動してアプリを更新

> Git Bash から実行すると自動で WSL (Ubuntu) 経由の rsync に切り替わる。

## 7. セキュリティ方針

| 項目 | 対応 |
|------|------|
| DB パスワード | Terraform で自動生成・`tfstate` に保存（Git 管理外） |
| RDS アクセス | EC2 のセキュリティグループからのみ許可（インターネット非公開） |
| SSH アクセス | 公開鍵認証のみ（パスワード認証なし） |
| 環境変数 | `.env` ファイルは `.gitignore` で除外 |
| HTTPS | 学習目的のため未対応（HTTP のみ） |
