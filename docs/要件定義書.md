## 1. プロジェクト概要

### 1.1 プロジェクト名
レシピ管理アプリ（RecipeManagement）

### 1.2 目的
日常的に料理するユーザーが、自分のレシピを一元管理できる Web アプリケーションを作成する。
レシピの登録・閲覧・編集・削除に加え、画像投稿・カテゴリ分類・お気に入り登録・検索機能を提供し、料理の記録と活用を支援する。

### 1.3 背景
プログラミングスクール初級編の最終課題として開発する。
学習した技術（Next.js・MySQL・Docker）を組み合わせ、実際の Web アプリケーション開発の一連の流れを体験することを目的とする。

### 1.4 対象ユーザー
- 自分のレシピを管理したい個人ユーザー
- スマートフォン・PC の両方から利用するユーザー

## 2. システム概要

### 2.1 システム構成

```
[ユーザー（ブラウザ）]
        ↕ HTTP
[Next.js アプリ（EC2）]
  ├── フロントエンド（App Router + Tailwind CSS）
  └── バックエンド（API Routes）
        ↕ Prisma ORM
[MySQL データベース（RDS）]
```

### 2.2 技術スタック

| 役割 | 技術・バージョン |
|------|----------------|
| フロントエンド + バックエンド | Next.js 16（App Router） |
| 言語 | TypeScript |
| ランタイム | React 19 |
| データベース | MySQL 9.7 LTS |
| ORM | Prisma 5.x |
| スタイリング | Tailwind CSS 4.x |
| アイコン | Lucide React |
| コンテナ（開発） | Docker Compose（MySQL のみ） |
| コンテナ（本番） | Docker（Next.js アプリをコンテナ化） |
| パッケージマネージャー | pnpm |
| ホスティング | AWS EC2（t2.micro） |
| DB ホスティング | AWS RDS（db.t3.micro、MySQL ※本番時は対応バージョンを要確認） |

## 3. 機能要件

### 3.1 機能一覧

| 機能ID | 機能名 | 優先度 | 詳細 |
|--------|--------|--------|------|
| F-01 | レシピ一覧表示 | 必須 | 画像・レシピ名・カテゴリをカード形式で表示。カテゴリごとにカード背景色を変えて視覚的に分類 |
| F-02 | レシピ詳細表示 | 必須 | 全情報・画像を1ページで確認。表示順：説明文 → 材料 → 作り方 → ポイント・コツ |
| F-03 | レシピ登録 | 必須 | 画像アップロード付き入力フォーム。材料は材料名・分量を個別入力、作り方は番号付きステップ形式、ポイント・コツ欄あり |
| F-04 | レシピ編集 | 必須 | 既存データを編集・保存。フォーム構成は F-03 と同一 |
| F-05 | レシピ削除 | 必須 | 確認ダイアログ付き削除・画像ファイルも削除 |
| F-06 | 画像アップロード | 必須 | JPEG/PNG/WebP/GIF・4MB 以下 |
| F-07 | カテゴリ分類 | 必須 | 10種類のカテゴリから選択・フィルタ。未選択時は「その他」を自動設定 |
| F-08 | お気に入り登録 | 必須 | ハートボタンでトグル・フィルタ |
| F-09 | キーワード検索 | 必須 | レシピ名・材料を部分一致検索 |
| F-10 | カテゴリフィルタ | 必須 | カテゴリで一覧を絞り込み |
| F-11 | お気に入りフィルタ | 必須 | お気に入り登録済みのみ表示 |
| F-12 | 並び替え | 必須 | 新着順・古い順・名前順・調理時間順の4種類で並び替え |

### 3.2 画面一覧
→ 詳細は [画面設計書.md](画面設計書.md) および [画面遷移図.md](画面遷移図.md) を参照

| 画面ID | 画面名 | URL |
|--------|--------|-----|
| S-01 | レシピ一覧 | `/` |
| S-02 | レシピ登録 | `/recipes/new` |
| S-03 | レシピ詳細 | `/recipes/[id]` |
| S-04 | レシピ編集 | `/recipes/[id]/edit` |

### 3.3 API 一覧
→ 詳細は [API仕様書.md](API仕様書.md) を参照

| Method | エンドポイント | 機能 |
|--------|--------------|------|
| GET | `/api/recipes` | 一覧取得（検索・フィルタ対応） |
| POST | `/api/recipes` | レシピ作成 |
| GET | `/api/recipes/[id]` | 1件取得 |
| PUT | `/api/recipes/[id]` | レシピ更新 |
| DELETE | `/api/recipes/[id]` | レシピ削除 |
| PATCH | `/api/recipes/[id]/favorite` | お気に入りトグル |
| GET | `/api/categories` | カテゴリ一覧取得 |
| POST | `/api/upload` | 画像アップロード |

## 4. 非機能要件

| 分類 | 要件 |
|------|------|
| レスポンシブ対応 | スマートフォン（320px〜）・タブレット・PC すべてで正常動作すること |
| パフォーマンス | 一覧ページの初期表示は 3 秒以内 |
| セキュリティ | アップロードファイルの MIME タイプ・サイズを API 側で検証する |
| セキュリティ | SQL インジェクション対策は Prisma ORM によって担保する |
| 可用性 | AWS 無料枠（12ヶ月）の範囲内で動作すること |
| 開発環境 | Docker Compose 1コマンドでローカル DB を起動できること |

## 5. 制約・前提条件

| 分類 | 内容 |
|------|------|
| 技術制約 | Java および React（単体）は使用禁止（スクール規定） |
| 技術制約 | PostgreSQL は使用禁止（スクール規定） |
| インフラ制約 | AWS 無料枠の範囲内で構築する |
| インフラ制約 | 画像は EC2 ローカルディスク（`public/uploads/`）に保存（S3 不使用） |
| 認証 | ユーザー認証機能はスコープ外（単一ユーザー前提） |

## 7. 用語定義

| 用語 | 説明 |
|------|------|
| レシピ | 料理の材料・作り方・画像などをまとめた1件のデータ |
| カテゴリ | レシピを分類するためのグループ（ご飯、麺類 など）。全10種類 |
| ポイント・コツ | レシピに付随するおいしく作るためのヒント・コツ（任意入力） |
| お気に入り | ユーザーがよく使うレシピにマークをつける機能 |
| App Router | Next.js 13 以降の新しいルーティング方式 |
| ORM | データベースをオブジェクトとして操作するライブラリ（今回は Prisma） |
| シード | 初期データをデータベースに投入する処理 |
